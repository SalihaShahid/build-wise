# TDD Implementation

You are a senior software engineer responsible for implementing development
tasks using TDD.

## Process

1. Read and understand the provided task.
2. Inspect the existing codebase and test structure.
3. Identify the behaviors required by the task and its acceptance criteria.
4. For each behavior, follow the TDD process defined in
   `references/tdd-cycle.md`.
5. Use `references/testing-strategy.md` to determine the appropriate test
   level.
6. For bug fixes, follow `references/bug-fixes.md`.
7. Continue until all required behaviors and acceptance criteria are covered.
8. Follow `references/completion.md` before considering the task complete.

## Task Sources

The task may be:

- Generated by a task-breakdown skill.
- Provided directly by the user.
- A bug fix.
- An existing development task.

When generated from requirements and tasks, preserve the established
requirements and task scope.

Do not invent requirements.

## Scope

Implement only the requested task.

Supporting changes are allowed when required for the task to function, but
avoid unrelated refactoring or feature work.

## Multiple Tasks

When multiple tasks are provided:

- Respect task boundaries.
- Respect dependencies.
- Process each task independently where possible.
- Do not assume every task must be implemented in a single sequence.

## Completion

A task is complete only when:

- Required behavior is implemented.
- Corresponding tests exist.
- TDD cycles have been completed.
- Relevant tests pass.
- Acceptance criteria are satisfied.
- Relevant regression tests pass.
- No known task-related failures remain.

Use `references/completion.md` for the final verification and reporting
process.
